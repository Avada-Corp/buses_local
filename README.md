# Берёзовка АК · автобусы

Одностраничное расписание автобусов, проходящих через остановку **Берёзовка АК**,
с фильтрами по дню недели, направлению («из Берёзовки» / «в Берёзовку») и населённому пункту.

## Как открыть

Скачайте/скопируйте `index.html`, `data.js`, `manifest.json`, `sw.js` и папку `icons`
в одну папку и откройте `index.html` в браузере (двойным щелчком, без сервера —
страница работает и с `file://`).
Телефон: перенесите файлы в память устройства и откройте `index.html`,
либо положите папку на любой хостинг.

## PWA: установка на телефон и офлайн

Страница — PWA: её можно поставить на главный экран, и она открывается без интернета
(расписание кэшируется service worker'ом, а при наличии сети всегда подтягивается свежее).

Для этого нужен **HTTPS** (или `http://localhost` при локальной проверке). По `http://IP`
страница работает как обычная: service worker просто не регистрируется.

Самый простой способ получить HTTPS бесплатно — GitHub Pages, пошагово в
[deploy/GITHUB-PAGES.md](deploy/GITHUB-PAGES.md). Локальная проверка:

```sh
python -m http.server 8423     # открыть http://localhost:8423/
node _tools/check_pwa.js       # манифест, service worker, офлайн — автотест
```

Если добавляли или переименовывали файлы в списке `PRECACHE` внутри `sw.js` —
поднимите там `VERSION` (`v1` → `v2`): старый кэш удалится при следующем запуске.
Обновление `data.js` правок в `sw.js` не требует — данные всегда берутся из сети.

Что умеет страница:

- по умолчанию — **ближайшие рейсы на сегодня** (8 штук), с чипами «через N мин»;
- фильтр по дню недели (кнопки «Сегодня» + Пн…Вс) и по направлению;
- фильтр по **населённому пункту**: показываются все рейсы, которые идут до этого пункта,
  включая **сквозные** (помечены значком «сквозной» и подписью «далее до …»);
- нажатие на рейс раскрывает **все остановки маршрута** с временами, километрами
  и полным названием маршрута из источника;
- выбранное направление, пункт, «весь день» и тема запоминаются в браузере (localStorage);
- **напоминания о ближайших рейсах** (колокольчик в шапке): настраивается число рейсов (1–3),
  за сколько минут напомнить (0/5/10/15) и учитывать ли фильтр по пункту. Пока страница открыта,
  наверху показывается «живая» полоса с ближайшими рейсами, ближайший подсвечивается и сигналит
  (заголовок вкладки, вибрация, звук). Направление берётся из выбранной вкладки, список сам
  сдвигается, когда ближайший рейс уходит.

  Ограничение: системные уведомления браузер выдаёт только в защищённом контексте (HTTPS или
  `localhost`), поэтому на `http://IP` напоминания показываются на самой странице; для настоящих
  уведомлений нужен HTTPS (см. [deploy/GITHUB-PAGES.md](deploy/GITHUB-PAGES.md)). На телефоне
  уведомление показывается через service worker — иначе Android его не поддерживает.
  Уведомления работают, пока приложение открыто (фоновая доставка при закрытом приложении
  требует push-сервера).

## Как обновить расписание

Данные берутся с [ticketbus.by](https://ticketbus.by/) (официальная продажа билетов по Беларуси).

```sh
node _tools/scrape_ticketbus.js     # скачивает табло Берёзовки и схемы всех рейсов -> _tools/live/
node _tools/build_live_data.js      # собирает data.js для страницы
node _tools/check_data.js           # проверяет структуру данных (должно быть «проверки пройдены ✔»)
node _tools/check_pwa.js            # необязательно: манифест, service worker, офлайн-режим
```

Нужен Node.js 18+ (используется `fetch`). После обновления `data.js` достаточно
перезагрузить страницу — дата обновления подставляется в подвал автоматически.

## Как положить на сервер (по IP)

Страница статическая: нужны только `index.html` и `data.js`. Самый короткий путь на
любом Linux-сервере — отдать папку питоном:

```sh
sudo mkdir -p /var/www/berezovka
scp index.html data.js user@IP:/var/www/berezovka/
ssh user@IP 'cd /var/www/berezovka && nohup python3 -m http.server 8423 --bind 0.0.0.0 >/tmp/berezovka.log 2>&1 &'
```

Открывать `http://IP:8423/`. Постоянный вариант (переживает перезагрузку) — systemd-юнит
`deploy/berezovka-http.service`; если стоит nginx — конфиг `deploy/berezovka-nginx.conf`
(отдельный порт или подпапка вида `http://IP/bus/`). Подробности и остальные способы
(docker, caddy, разбор «почему не открывается») — в [deploy/README.md](deploy/README.md).

Готовые файлы для загрузки через панель хостинга: `deploy/berezovka-site.zip`
(пересобирается командой `deploy\make-zip.ps1`).
Заливка по SSH из Windows: `deploy/upload.ps1 -Server IP`.

## Файлы

| Файл | Что это |
| --- | --- |
| `index.html` | страница целиком: разметка, стили, скрипт |
| `data.js` | данные расписания (`window.SCHEDULE`), генерируются сборщиком |
| `manifest.json` | манифест PWA: имя, иконки, запуск без адресной строки |
| `sw.js` | service worker: офлайн-кэш, клик по уведомлению |
| `icons/` | иконки приложения (192/512, maskable, apple-touch, badge) |
| `.nojekyll` | пустой файл для GitHub Pages (отключает сборку Jekyll) |
| `.gitignore`, `.gitattributes` | что не коммитить (сырые данные, скриншоты, архив) и LF-переводы строк |
| `_tools/scrape_ticketbus.js` | загрузка данных с ticketbus.by |
| `_tools/build_live_data.js` | сборка `data.js` из `_tools/live/board.json` |
| `_tools/check_data.js` | проверка `data.js` (время, дни, остановки, дубликаты) |
| `_tools/page_script.js` | исходник скрипта страницы (вставляется в `index.html`) |
| `_tools/make_icons.js` | перерисовка иконок в `icons/` (headless Chrome) |
| `_tools/check_pwa.js` | автотест PWA: манифест, service worker, офлайн |
| `_tools/preview.js` | скриншот/замер страницы через Chrome DevTools Protocol |
| `_tools/live/` | сырые данные последнего сбора |
| `deploy/` | инструкции по заливке (SSH/nginx/docker и GitHub Pages), готовые конфиги, `upload.ps1`, `make-zip.ps1`, архив сайта |
| `_tools/*.py`, `_tools/fload_*.json` | старая цепочка по сохранённой странице `fload.htm` (не используется) |

## Особенности источника

- Время местное (UTC+3). На табло встречаются обе версии расписания сразу
  («… / отменяется с 17.10.26» и «… / вводится с 17.10.26;») — сборщик оставляет
  только действующую на дату сбора.
- Один и тот же рейс бывает продублирован строками «в продаже» и
  «продажа только в автобусе» — остаётся одна.
- Рейсы «с заездом» в Минск в источнике называются «ЗАЕЗД АВ-Центральный МИНСК»;
  в карточке такой пункт показывается как «Минск (заезд)».
